- 対象資料（全文投入と他の方式で範囲が違う点も記録）：全文投入は教材JSONにある全9資料・438ページ（227,971文字）。ベクトル検索・Tree・Graphは第1〜3回の本講義214ページ。

- 検索だけを実行して見つかったページと、その本文で確認できたこと：
  - `uv run python -m app.retrieval "LoRA QLoRA 違い"` の結果、上位5件（第2回・PDF p.52, p.51, p.60, p.47, p.61）を取得した。
  - 1位（p.52）および2位（p.51）の本文にて、質問への直接の根拠が確認できた。
  - 3〜5位（p.60, p.47, p.61）は「QLoRA」「LoRA」の単語が含まれる演習手順やRAG比較のスライドであり、用語は共通しているものの質問の直接的な根拠ではないと判別できた。
- `--trace`で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：
  - 全文投入：ツール呼び出しなし（プロンプトに全資料を直接投入、モデル応答1回）。
  - ベクトル検索：`search_materials({'query': 'LoRA QLoRA 固定 学習'})` を1回呼び出し（モデル応答2回）。
  - Tree：`browse_tree` を計4回呼び出し、階層をたどって末端ページの本文を取得した（モデル応答5回）。
    1. `browse_tree({})` → 講義一覧（`lec01-main`, `lec02-main`, `lec03-main`）を取得
    2. `browse_tree({'node_id': 'lec02-main'})` → 第2回の章・ページ一覧を取得
    3. `browse_tree({'node_id': 'lec02-main-s045'})` → 「選んだモデルを、いつ・どう直すか」の章内の各ページ先頭文を取得
    4. `browse_tree({'node_id': 'lec02-main-p052'})` → p.52の全文（717文字）を取得
  - Graph：`search_graph({'query': 'LoRA QLoRA 固定 学習'})` を1回呼び出し、`lec02-main-p052` 等を入口（seeds）として周辺ノードを探索（モデル応答2回）。
- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：
  - 取得できたのに回答へ使えなかった例：全文投入では入力内に該当ページ（p.51, 52）が含まれており、場所の特定までは正確にできていたにもかかわらず、直接の答えではなく「考えるためのヒント」のみを出力し、質問への直接回答にならなかった。
  - 不要な情報が含まれた例：ベクトル検索の上位5件やGraphの周辺探索（最大10ページ）では、答えの根拠（p.51, 52）以外に演習手順や関連スライドも取得されたが、LLMが取捨選択をして正しく回答した。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  - 採用したい方式：ベクトル検索（通常のRAG）。
  - 理由：今回の質問のような特定の概念・用語の定義を問うケースでは、最も高速（2.72秒）かつ最小のトークン数（3,027 tokens）・最小コスト（$0.001321）で正確な根拠ページを取得し回答できたため。
  - 比較条件の限界：単一ページ（p.52）で答えが完結する質問のみで比較したため、複数章をまたぐ統合的な質問や全体要約におけるTree・Graph・全文投入の優位性は検証できていない。
- 気づき・疑問：
  - 全文投入は「コンテキストにすべての情報が入っていれば確実に正しく答えてくれる」とは限らず、入力トークンが膨大（約11.7万tokens）になることで指示の解釈や出力の挙動が不安定になることがあると分かった。
  - Tree方式は検索DBや埋め込みモデルが不要で目次構造だけで正確にp.52へ到達できた点が興味深いが、ステップごとにLLMを往復するため応答回数（5回）と時間（6.28秒）が増えるトレードオフがある。

## 宿題

- 取り組んだレベル：基礎
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：
  - `app/config.py` の検索件数設定 `RAG_TOP_K` を変更した（変更前：`RAG_TOP_K = 5` → 変更後：`RAG_TOP_K = 1` および `RAG_TOP_K = 10` の2パターンを検証）。
- 比較した質問と、固定した条件（モデル・対象資料など）：
  - 質問：`第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？`
  - 固定した条件：回答モデル `gemini-3.5-flash-lite`、検索方式（通常のベクトル検索 `search_materials`）、対象資料（第1〜3回の本講義214ページ `lec01-main`, `lec02-main`, `lec03-main`）。
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：
  - 変更前（`RAG_TOP_K = 5`）
    - 回答・根拠：正解（LoRAは元の重みを固定し低ランクの2行列の積を学習、QLoRAは4bit圧縮を追加）。引用は第2回・PDF p.51, 52。
    - `--trace`・数値：`search_materials({'query': 'LoRA QLoRA 固定 学習'})` を1回呼び出し / 時間 2.72秒 / 入力 3,027 tokens・出力 165 tokens / モデル応答 2回 / 推定費用 `$0.001321 USD`
  - 変更後_1（`RAG_TOP_K = 1` に削減）
    - 回答・根拠：正解（元の重み $W$ を固定し行列 $A, B$ の差分を学習、QLoRAは4bit圧縮を追加）。1位ヒットのみで回答したため引用は第2回・PDF p.52 のみ。
    - `--trace`・数値：`search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'})` を1回呼び出し / 時間 2.62秒 / 入力 1,191 tokens・出力 148 tokens / モデル応答 2回 / 推定費用 `$0.000727 USD`
  - 変更後_2（`RAG_TOP_K = 10` に増加）
    - 回答・根拠：正解（内容は変更前とほぼ同等）。引用は第2回・PDF p.51, p.52。
    - `--trace`・数値：`search_materials({'query': 'LoRA QLoRA 固定 学習'})` を1回呼び出し / 時間 3.36秒 / 入力 5,187 tokens・出力 212 tokens / モデル応答 2回 / 推定費用 `$0.002086 USD`
- 改善した例と、残る失敗・制約：
  - 改善した点：`RAG_TOP_K = 1` に絞った場合、最も関連度の高い1ページ（p.52）に答えのすべてが凝縮されていたため、回答の正確性を損なうことなく入力トークン数を約61%削減（3,027 → 1,191 tokens）、推定API費用を約45%削減（$0.001321 → $0.000727）できた。
  - 残る失敗・制約：逆に `RAG_TOP_K = 10` に増やした場合は、3位〜10位に入るノイズ（演習手順など）が増えるだけで回答の質は向上せず、入力トークン数とコストが大幅に増加（`K=1` 比で約4.3倍のトークン・約2.9倍のコスト）する過剰取得のデメリットが確認された。一方、`K=1` の設定は「単一ページに答えが収まっている質問」には最適だが、複数ページにまたがる質問では2位以降の根拠を取りこぼす制約がある。
- 気づき・疑問：
  - 検索件数 `RAG_TOP_K` は「多ければ多いほど良い」わけではなく、質問の性質（単一ページ完結か、複数ページ統合か）に応じて入力トークン数（コスト・遅延）と網羅性のトレードオフが直接数値（API費用）として表れることが実感できた。
